# 🤖 Архитектура мультиагентной системы автоматизации CI/CD

В данном репозитории описана структура и логика работы автономной системы ИИ-агентов, предназначенной для автоматического анализа задач, генерации патчей кода и их валидации.


## 🎯 Ключевые элементы на схеме

*   📥 **Входные данные:** Тикет с задачей (`GitHub/GitLab Issue`) и прямая ссылка на исходный репозиторий для анализа кода.
*   🧠 **Узлы системы:** 
    *   **Главный ИИ-агент (Оркестратор)** — координирует распределение задач и управляет общим жизненным циклом выполнения.
    *   **Агент-Исследователь** — отвечает за навигацию и контекстный поиск по кодовой базе.
    *   **Агент-Писатель** — осуществляет непосредственную модификацию файлов и генерацию фичи.
    *   **Агент-Тестировщик** — запускает проверочные сценарии для верификации изменений.
*   🛠️ **Инструменты (Tools):** Вызовы системных утилит `grep` для поиска, `patch_file` для точечного редактирования и запуск тестов через фреймворк `pytest`.
*   🔄 **Шаг внешней проверки:** Бинарная валидация прохождения тестов по системному коду возврата (`Exit Code`). В случае обнаружения ошибок активируется **петля обратной связи** (автоматический возврат упавшего кода Агенту-Писателю на доработку).
*   👥 **Точка подтверждения человеком:** Механизм безопасного развертывания через создание изолированного `Draft Pull Request` со всеми сопутствующими логами для ручного `Code Review` перед финальным слиянием изменений в ветку `main`.
*   🚨 **Безопасность:** Вынесенная кнопка аварийной остановки (**Kill-switch**), позволяющая моментально отозвать права доступа и полностью прервать работу всей автоматизированной системы в случае нештатной ситуации.
